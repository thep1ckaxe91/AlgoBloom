# T15 — Chất lượng và bảo vệ

**Người phụ trách:** Long (`@LongSei`).

**Trạng thái:** Nhánh chuẩn bị. Checklist chưa chọn là việc chưa có bằng chứng hoàn thành.

## Yêu cầu mốc
T15 không lặp lại demo T14. Cần functional/integration/security/performance evidence, lifecycle plan, quickstart, final report và release/tag của nhóm sau nghiệm thu. Slide nhóm 8–12 trang; phần lớn demo dành cho bằng chứng chất lượng.

## Checklist Long
- [ ] Cập nhật nhánh theo main có MVP T14 đã nghiệm thu; ưu tiên sửa lỗi và regression, không mở rộng kiến trúc phút cuối.
- [ ] Chạy test suite, ghi pass/fail/skipped, coverage nếu có và phần chưa kiểm thử; không đặt sẵn số liệu thành công.
- [ ] Load test với môi trường, commit/config, workload, concurrency, thời lượng/warm-up, provider/quota/cache state rõ ràng; đo p50/p95, throughput và error rate.
- [ ] Tách benchmark mock khỏi live provider; số mock không đại diện latency/capacity Gemini. Nếu giới hạn quota thì báo giới hạn và phần chưa đo.
- [ ] Chỉ ra bottleneck và đo trước/sau một cải tiến với cùng điều kiện; không công bố cải thiện nếu chưa đo.
- [ ] Security review internal key, input limits, secret redaction, timeouts/retry/rate limits; phối hợp Gateway thử unauthorized/forbidden và truy cập chéo người dùng. API key nội bộ không thay RBAC public.
- [ ] Viết kịch bản v1 → v2 với thay đổi breaking cụ thể ở API công khai của nhóm, tác động consumer, compatibility, migration/deprecation/notification và rollback. Không đổi endpoint AI P0 chỉ để có demo.
- [ ] Viết quickstart consumer và integration example; operational checks, monitoring/failure runbook, release/maintenance plan.
- [ ] Tổng hợp hạn chế, yêu cầu ban đầu so với kết quả, contribution links và phần bảo vệ của Long; báo cáo 1–2 trang + final report nhóm theo yêu cầu.
- [ ] Chỉ đề xuất tag/release sau khi code tích hợp và test evidence được duyệt. Nhánh version không phải final release, chưa tạo tag trong bước chuẩn bị.
